# Chapters 151–181 — 1학년 C Programming 교육 품질 재검토
**검토일:** 2026-11-15
**기준:** `docs/C_PROGRAMMING_AUTHORING_STANDARD.md`

## 1. 종합 결론
각 단원의 학습 단계 수를 **8개로 강제하지 않는다**. 다만 현재 네 단원은 서로 구분되는 개념과 탐구 활동이 있어 8개를 유지해도 교육상 의미가 있다. 필수와 선택의 경계를 명확히 하여 1학년 학생이 주요 역량을 잃지 않고 학습 부담을 조절할 수 있도록 한다.

| ID | 핵심 Core | 선택 Optional | 직접 코딩 과제 우선순위 |
|---|---|---|---|
| 151 | 6단계: 값/주소, 역참조, 원본 수정, swap, 배열·포인터 산술, 범위·수명 | 2단계: const 포인터, 이중 포인터 | P1–P4 Core (주소·swap·배열 순회·범위 확인), P5 output parameter와 P6 센서 평균은 Optional |
| 161 | 6단계: Record 필요성, struct/typedef, .·->, 구조체 배열, 함수 전달, 값 복사 | 2단계: padding/sizeof, 텍스트 저장 형식 | P1–P5 Core, P6 CSV 파일 실습은 Optional (171에서 상세 학습) |
| 171 | 8개 실습 단계 유지: 파일 필요성, Stream, 모드, 텍스트 읽기·쓰기, EOF·오류, 구조체 Record, 센서 로그, 종합 점검 | 각 단계의 펼침형 추가 설명과 확장 실습 | P1 쓰기, P2 읽기·평균 우선, P3–P6은 진도에 따른 확장 |
| 181 | 4단계: 동적 할당 필요성, malloc/sizeof/NULL, 동적 배열과 포인터, free/수명 | 4단계: calloc, realloc, 메모리 디버깅, 동적 Sensor 레코드 | P1–P3 Core, P4–P6 Optional |

현재 8개라는 숫자가 같더라도 **필수 교육량과 상세 개념이 동일하지 않다**. 다음 개편에서는 실제 목표에 따라 단계 통합·추가·삭제를 자유롭게 판단한다.

## 2. 단원별 교육 내용 평가

### 151 — Pointers
- **개선:** 안전성까지를 기본 포인터 역량으로 묶고, const와 이중 포인터는 Optional로 이동. 배열 포인터 산술 다음에 범위/수명 안전성을 배치함.
- **이해 목표:** `x`, `&x`, `*p`의 차이, 주소 전달과 값 전달의 차이, `a[i]`와 `*(a+i)`의 관계. one-past는 형성 가능하나 역참조할 수 없음.
- **오개념 방지:** C는 엄밀히 값 전달이며 call-by-reference 문법이 아니다. 포인터 +1은 1바이트 이동이 아니라 다음 원소이다.
- **직접 코딩:** 핵심 과제 P1–P4(값 출력·swap·배열 순회·범위 검사)를 우선합니다. P5 out-parameter와 P6 센서 평균은 선택 심화로 두어 코딩 부담을 조절합니다.

### 161 — Structures
- **개선:** 구조체 배열·함수 전달을 Core로 전진 배치하고 값 복사도 Core에 포함. 구조체 패딩/메모리 배치, CSV 직렬화는 Optional로 구분.
- **C 정확도 수정:** `sizeof(struct S)`의 구체적인 숫자를 출력하던 플랫폼 의존 예제를, `sizeof(struct S) >= sizeof(char)+sizeof(int)`의 참/거짓 확인 코드로 변경함. `%d`는 결과 `int` 타입과 일치. GCC C11에서 결과 1 확인.
- **과제 조정:** P5의 모호한 서술형 참조 출력을 `70 90`으로 바꾸고, 분리된 구조체 복사를 관찰하도록 수정. P6 CSV는 171에 넘겨도 됨.
- **유의:** 구조체 대입은 필드 값을 복사하지만 포인터 멤버가 가리키는 데이터는 깊은 복사하지 않는다.

### 171 — File I/O
- **판단:** 기존 화면이 151/161/181과 다른 독립 인터랙티브 엔진 및 다양한 안전성 실험(파일 모드, EOF/형식 불일치, 센서 자료)을 포함하므로 **안전하게 보존**한다. 핵심 8단계는 현재 개념상 독립적인 목표를 갖는다.
- **개선:** 첫 페이지에 코딩 우선순위(P1 쓰기·닫기, P2 읽기·반환값·평균)를 명확히 함. P3~P6은 학습 진도에 따른 확장으로 안내함.
- **핵심 필수:** `fopen` 실패, 모드 `r/w/a`, `fprintf/fscanf/fgets`, `fscanf` 변환 성공 개수 및 EOF·형식 불일치 구분, `fclose`.
- **표기 유의:** Chapter 17/교재 코드 171과 페이지 내 교재 절 `§7.x` 참조는 서로 다른 표기임. 교재의 실제 절 번호를 재확인하지 않고 일괄 변환하지 않음.
- **추후 개선:** 독립 엔진을 공통 `journey.js`로 이관하는 것은 회귀 위험이 높으므로 이번 범위에서 제외함.

### 181 — Dynamic Memory
- **Core 4 유지:** `malloc(n*sizeof *p)`, `NULL` 확인, 요소 초기화 및 접근, `free`와 객체 수명. 모든 인스턴스의 메모리를 정확히 한 번 해제해야 함.
- **Optional 4 유지:** calloc/realloc/디버깅/센서 구조체. 임시 포인터를 사용한 `realloc` 오류 처리와 별칭(aliasing) 위험을 학습.
- **부담 완화:** P1의 필수 과제에서 대규모 크기 곱셈 오버플로 검사를 요구하지 않음. Core에서는 정상적인 작은 `n`의 실행을 다루고 안전한 확장 검사는 선택 심화로 둠.
- **`calloc` 설명 정확성:** 모든 바이트를 0으로 초기화한다는 점과 일반적인 C 정수 값의 0을 구분. 다른 자료형(특히 포인터)의 의미상 0까지 일반화하지 않음.
- **주의:** `free(p)`는 자동으로 `p=NULL`을 실행하지 않으며, `p=NULL`도 다른 별칭을 정리하지 못함.

## 3. 사이트 적용 내용

- `journey.js`는 `coreCount`가 정수이고 전체 단계보다 작으면 **어느 단원에서나 Core/Optional** UI·진도 구분을 지원한다.
- `practice-engine.js`는 `practiceCoreCount`로 과제별 필수/선택 라벨을 구분한다.
- 개편에 따라 151/161/181의 `contentRevision`을 증가시켜 단계 순서가 바뀐 이전 활동 기록이 잘못 연결되는 현상을 방지한다. 코딩 과제의 순서·Starter Code가 바뀐 경우 `practiceRevision`을 사용하여 이전 초안이 다른 과제에 잘못 연결되지 않게 한다.
- 171은 기존 파일 I/O 인터랙티브 모델과 로컬 활동 기록을 보존한다.
